5. Existing Authentication System
Human staff: corporate SSO + MFA; roles sourced from IAM/Directory.
AI service: OAuth 2.0 client credentials or workload identity; separate identities per environment.
Customer verification: registered-mobile OTP or other organization-approved factor. Verification state expires after a short configured period.
Service-to-service calls: TLS; mTLS preferred for sensitive internal APIs; secrets stored in a managed secret vault.

6. Integration Error Handling
Condition
AI Behavior
CRM timeout
Do not invent customer status. Retry within policy, then offer human/ticket fallback.
Billing unavailable
Do not state balance/payment/expiry as fact; explain temporary lookup issue.
NMS/OLT API unavailable
Continue safe manual indicator checks; mark telemetry unavailable in ticket.
AAA API returns unknown
Do not assume authentication failure; escalate or create diagnostic ticket.
Write API returns 4xx
Do not claim ticket/order was created; surface failure and transfer/fallback.
Write API times out after request
Use idempotency key/query before retry to avoid duplicate ticket/order.
Outage API lacks ETA
Tell customer restoration is in progress if approved, but do not fabricate ETA.
