1. Purpose of This Pack
This pack provides realistic ISP-specific sample documents for developing and validating a Phase 1 AI-native contact center. It is designed to test voice conversations, retrieval-augmented generation (RAG), CRM/Billing/NMS integrations, Asterisk/SIP telephony, customer verification, ticketing, escalation, security and human handoff.
2. ISP Scope Covered
Residential and SME FTTH broadband support (GPON/XGS-PON terminology used as test examples).
Common intents: no internet, LOS red, slow speed, Wi-Fi issue, intermittent connectivity, payment/renewal, account suspension, package upgrade/downgrade, new connection, relocation, static/public IP, complaint, outage and human-agent request.
Network-aware diagnosis using CRM, Billing/ERP, AAA/RADIUS, BNG/session, OLT/ONU/NMS, ACS/TR-069 and outage/service-status sources.
English and Nepali conversational samples with room to add Hindi or other languages.
Human escalation to Customer Care, NOC L1/L2, Field Operations, Billing, Sales/Retention and Security/Fraud queues.

5. Acceptance Criteria
Grounded responses: do not hallucinate outage, package price, payment, session, ONU state, ticket status or ETA.
Correct fault-domain separation: customer Wi-Fi/device vs CPE/ONU vs access PON/OLT vs AAA/BNG vs core/upstream vs billing/provisioning.
Account-specific data requires the configured verification level.
Every write action (ticket/order/callback) is logged with call ID, customer ID, action, result and consent where required.
Human handoff includes intent, language, verification status, diagnostic findings, actions completed, ticket/outage references and unresolved issue.
Test credentials and private infrastructure values remain synthetic and never become production defaults.
